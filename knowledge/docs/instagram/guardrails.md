# Engineering guardrails from the saved posts

| Principle | Workspace behavior |
| --- | --- |
| Scope and restraint | Preserve requested features; reuse existing code; avoid speculative frameworks and unrelated edits. |
| Better context | Read small current task context and exact resolved files before broad searches. |
| Verifiable completion | Report actual commands and evidence, distinguishing skipped or unavailable checks. |
| Tests that detect failures | Use independent expected values, intended role/record/locator, and focused failure-sensitivity checks when useful. |
| Framework ownership | Existing microservice and Playwright guides own their source, test, mockserver, and deployment boundaries. |
| Coordination | Assign file ownership for authorized parallel work and retain handoffs; ordinary tasks do not require an agent team. |
| Security evidence | Confirm the affected boundary and impact; keep unresolved hypotheses separate from confirmed findings. |
| Context economics | Measure quality and usage together. Cache/provider/model claims need telemetry; fewer tokens alone is not success. |
| Durable knowledge | Store useful acceptance criteria, decisions, vocabulary, and continuation notes; avoid empty document templates. |
| Source integrity | Track upstream revisions and licenses; a reel's benchmark or installation instruction is not verified workspace behavior. |

These rules are in AGENTS.md and the relevant skills. The full upstream catalogues remain references to avoid conflicting automatic processes. Communication stays concise and clear; the Caveman reference does not impose a dialect or suppress evidence.
